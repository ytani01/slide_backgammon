- 問題: 負けたほうは自分のスタートへ戻る（143 行）。そこは勝ったほうのゴールなので、勝ったほうはゴールの手前で、
  出直したばかりの相手と必ずもう一度ぶつかる。ゴールまでの残りが TOUCH（0.0425）より短くなると、相手が
  スタートに出た直後の 1 フレームで `gap <= TOUCH` になり、1.2 秒の戦いが始まる。この間、勝ったほうは
  1 回勝つごとに 1 フレーム分（60fps で 0.0055）しか進めないので、ゴールに着くには続けて 8 回前後勝つ必要がある。

  - 30fps で 30 分 × 3 回: 1, 3, 4 回
  - 出直した直後（スタートから 0.02 以内）に戦いになったのは 30 分で 27〜53 回。続けて起きた最長は 4〜8 回

## 問題の無かった点

- ぶつかる条件 `gap >= 0 && gap <= TOUCH`: 1 フレームで縮む gap は最大 2 × 0.33 × 0.05 = 0.033 で TOUCH（0.0425）より
  小さく、動いている同士がすれ違って抜けることは無い（シミュレーションで、2 本とも動いていて gap < 0 になったのは
  60fps で 0 回。30fps の 5 回はどれもゴールで止まった直後の正しいすれ違い）
- ゴールで止まっている間は戦わない（150 行の `hold <= 0` 2 つ）。止まっている間 `continue` で動かず、明けたフレームで
  スタートへ戻すだけで、そのフレームは進まない。止まったままになる並びは無い
- ゴールの判定 `(a.goal - a.s) * a.dir <= 0`: 白・茶色とも行き過ぎを `a.goal` に揃えてから止める。正しい
- 負けたほうを戻すタイミング: 戦いが終わったフレームで戻し（143 行）、同じフレームの `draw()` で火花も消える（114 行）
- 戦いの最中は `hold` を減らさないが、戦いはどちらも止まっていないときしか始まらないので影響なし
- 二重に動かない: `dataset.running` は svg 要素に付くので、同じ要素で 2 本目は 87 行で返る。画像の確認（`player.html:1797`）の
  `render()` で積まれた `setTimeout` も、div を document に入れないので別の svg を拾わない（コードを読んで確認、ブラウザでは未確認）
- 止める・動き直す: 描き直し（`player.html:1178` の `innerHTML`）で古い svg が外れ、次の `frame` の `isConnected` で止まる。
  2 枚目へ戻ると新しい svg になり、`running` が付いていないので動き直す。シークで同じスライドを描き直したときも、
  最初からやり直すだけ（コードを読んで確認）
- dash: 白は `[0, s]`、茶色は `stroke-dashoffset = -s` で `[s, s + len] = [s, 1]`。隙間 3 が全長 1 より長いので模様が繰り返さず、
  0 より手前もはみ出さない（計算で確認）。長さ 0.005 未満は隠すので丸い端の点も出ない
- 矢じりの向き: 両端でも `clamp` 後の 2 点は 0.002 離れるので向きが崩れない。茶色の s = 0（ゴール）では右向き、白の s = 1 も右向きで正しい
- `prefers-reduced-motion`: 向かい合った途中（0.45 と 0.55、gap 0.1 > TOUCH）で 1 回だけ描いて止まる。火花は出ない
- コメント: 83〜84 行は「なぜ render() から setTimeout で呼ぶか」を書いていて規約どおり。造語は無い
- 範囲: 差分は 2 枚目と、それが使う関数だけ。`images/k-arena1.jpeg` の未追跡は TODO-069 から残っているもので本件とは無関係
