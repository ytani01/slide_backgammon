## きっかけ

2026-09-30 に利用者の依頼で立てた。「バックギャモンの歴史は古い」のスライドで、
3 枚の図（約 5,000 年前の中東 → 世界中 → 飛鳥時代の日本）を矢印でつなぎ、
歴史の流れを示す。形は、矢印アイコン・山形・時間軸の 3 案から、利用者が
「図の下を通る時間軸」を選んだ。

## やったこと

`slides/backgammon.js` の 2 枚目の render() を、「図 → 時間軸 → 説明文」の 3 段にした。

- 横線（sky から lime のグラデーション）。最初は `h-[0.3cqw]` にしたが、利用者に
  「矢印が細すぎる」と言われた。0.8cqw の試し撮りでも「もっと太く」だったので、`h-[1.2cqw]` にした
- 右端の矢じり。最初は `fa-caret-right` にしたが、線の太さと合わせやすいよう、
  `clip-path` の三角形の div（`w-[3.2cqw] h-[3.8cqw]`）に替えた
- 点 3 つ（`w-[2.8cqw]`）。図と同じ `grid-cols-3 gap-[1.8cqw]` の grid に置き、各図の真下に来るようにした
- 説明文。利用者に「時間軸の上の文字をもう少し大きく」と言われ、
  `clamp(0.85rem, 1.85cqw, 1.35rem)` から `clamp(1.1rem, 2.3cqw, 1.7rem)` にした。
  2.5cqw では 1 枚目が「（中 / 東）」で折り返したので、2.3cqw に下げ、`whitespace-nowrap` を足した
- 続けて「文字の縦の位置がずれている。丸の下にして」と言われた。図の高さが違うので、
  図の下に付けた説明文の高さが揃っていなかった。説明文を図から外し、時間軸の下に別の
  grid で並べた（`cap()`）。`fig()` は画像だけを返すようにし、画像の grid に `items-end` を
  足して下端を揃えた。`fig()` を使うのは 2 枚目だけ
- 1 枚目の説明文はセルより 6.4px 広く、右にだけはみ出して中心が点から 3.2px ずれた。
  `cap()` を `flex justify-center` にして文言を `<span>` で包み、左右に均等にはみ出すようにした
- ナレーション・duration・説明文の文言は変えていない

## 分担の振り返り

- **verifier が見つけたこと**: 指示した項目の食い違いは無かった。指示していない所では、
  1 枚目の説明文の中心が 3.2px ずれていることを「判断が要る点」として挙げ、これを直した。
  `fig()` がほかのスライドにも効くか、という点も挙げた（2 枚目だけなので影響は無い）
- **見込みとの食い違い**: 担当の組み方は見込みどおり。ただし、利用者が見た目を 3 回直したので
  verifier を 4 回動かした（うち 1 回は途中で止めた）。見た目で決まる値を、利用者が
  見る前に verifier へ回したのが原因
- **次に同じ規模の項目をやるなら**: 太さ・文字の大きさ・配置のように見た目で決まるものは、
  main が 1 枚撮って利用者に見せ、全部決まってから verifier を起こす（CLAUDE.md の
  「利用者の指示が固まるまで、確認の担当を起こさない」）。測り方のスクリプトは verifier に
  1 本作らせて使い回させる。今回はセレクタがクラス名に頼っていて、クラスを変えたら点が
  0 個になったので、`data-` 属性で選べるようにしておくとよい
- verifier は 1 回目と 2 回目のあと、`pgrep -f "ytslide web"` で見つけたプロセスを全部 kill し、
  main が立てたサーバーまで止めていた。3 回目からは「main のサーバーは止めない、自分で
  立てた分だけ止める」と依頼に書き、止まらなくなった
